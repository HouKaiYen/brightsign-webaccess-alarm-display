# BrightSign / WebAccess 警報平面圖

Windows 主機向 WebAccess 取得警報，BrightSign 播放器開啟顯示網址。每個測點各自使用獨立圖面，警報文字在上方、該測點的圖示在下方；播放器沒有設定入口。

## 資料夾

| 資料夾 | 用途 |
| --- | --- |
| `server/config` | 伺服器環境設定 |
| `server/services` | WebAccess、警報狀態與設定保存 |
| `server/routes` | API 路由 |
| `src/management` | 管委會日常管理、媒體清單與跑馬燈 |
| `src/settings` | 工程測點設定、表單與平面圖編輯 |
| `src/display` | 獨立播放器顯示與連線 |
| `shared` | 前後端共用 TypeScript 型別 |
| `tests` | 警報規則與 API 測試 |
| `scripts` | 可攜式打包與啟動工具 |
| `data` | 執行時設定與上傳圖片，不納入 Git |
| `dist` | 建置後網頁，不納入 Git |

## 可攜式免安裝包（建議案場使用）

取得 `BrightSignAlarm-win-x64-*.zip` 後，解壓縮到案場固定位置，例如 `C:\BrightSignAlarm`。不需要安裝 Node.js、npm 或另行建置，使用套件內附的官方 Node.js 24 執行環境；目前支援 Windows 10/11、Windows Server 的 x64 環境。

1. 雙擊「開啟設定頁.cmd」，程式會啟動並開啟 `http://localhost:3006/settings`。
2. 從日常管理頁進入「工程設定」，點「WebAccess 連線設定」，輸入 WebAccess IP／服務網址、專案名稱、帳號及密碼，儲存後直接套用，不需重新啟動。
3. 上傳樓層圖並建立各測點的警報頁，BrightSign 使用 `http://主機IP:3006/display`。
4. 在工程設定頁點「系統控制」可開始／停止警報監控，停止時管理頁仍可操作。從主機的 localhost 設定頁可啟用／取消開機自啟動（不用先登入），首次啟用需 Windows 管理員授權；僅建立此資料夾對應的工作排程。
5. 如需關閉整個程式（包含管理頁），使用「停止警報系統.cmd」；若是開機以 SYSTEM 啟動，請以系統管理員執行停止操作。套件另附「啟用／取消開機自啟動.cmd」作為備用操作。

平時啟動不需系統管理員，但設定開機自啟動需要 Windows 管理員權限。主機必須能連到 WebAccess，播放器必須能連到主機；主機防火牆需允許案場內網連入設定的連接埠。若同機有多份套件，請在各份 `portable.config.json` 使用不同 port。

套件內的 `data` 是該案場的設定與圖片，更新時先停止程式，以新版本替換 `app`、`runtime` 與 `tools`，保留 `data`、`portable.config.json`。搬移資料夾前先取消舊位置的開機自啟動，再在新位置啟用。

WebAccess 密碼以 Windows DPAPI 本機範圍加密並限制連線設定檔的存取權限；API 只回傳是否有密碼，不回傳密碼內容。備份整個 `data`；移到另一台 Windows 主機時，須重新輸入連線密碼。設定頁僅供可信任的案場內網使用。

開發端產生免安裝包：`npm run package:portable`。產物在 `artifacts`，打包只複製程式與正式環境依賴，不包含 `.env`、既有 `data`、測試圖片或帳密。Node.js 執行檔會比對官方 SHA256 清單。
## Windows 系統匣

- 執行「啟動警報系統.cmd」或「開啟設定頁.cmd」時，會顯示系統匣圖示。按兩下可開啟設定頁，按右鍵可查看服務狀態、啟動、停止或重新啟動服務。
- 系統以開機排程啟動時，登入 Windows 後可執行「開啟系統匣圖示.cmd」。系統匣狀態每 10 秒檢查本機服務；結束系統匣程式不會停止服務。
- 若服務由 SYSTEM 或其他使用者啟動，停止或重新啟動可能需要系統管理員權限；請以管理員身分啟動系統匣，或使用原本的停止指令。

## Windows 管理員權限

| 操作 | 是否需要管理員權限 | 操作方式 |
| --- | --- | --- |
| 啟動警報系統、開啟設定頁、編輯內容、上傳媒體 | 通常不需要 | 一般雙擊即可；目前 Windows 使用者必須能寫入套件的 data 資料夾。 |
| 工程頁的「開始／停止警報監控」 | 不需要 | 在網頁操作即可；此操作只切換監控，不會關閉整個服務。 |
| 使用網頁啟用／取消開機自啟動 | 需要 | 在服務主機以 localhost 開啟工程頁；若服務尚未具備管理員權限，操作時會跳出 UAC，請同意或輸入管理員帳號。 |
| 執行「啟用開機自啟動.cmd」或「取消開機自啟動.cmd」 | 需要 | 在檔案上按右鍵 →「以系統管理員身分執行」。取消已建立的 SYSTEM 排程也需要管理員權限。 |
| 執行「停止警報系統.cmd」 | 視啟動方式而定 | 若由同一使用者一般啟動，可直接雙擊；若由開機排程以 SYSTEM 啟動，或由其他管理員啟動，請以系統管理員身分執行。 |
| 執行「修復連線設定權限.cmd」 | 需要管理員授權 | 請由平常使用本程式的 Windows 帳號直接雙擊，再同意跳出的 UAC。腳本會先記住該使用者，再要求提升權限。 |
| 新增 Windows 防火牆允許規則 | 需要 | 由系統管理員允許案場內網存取服務連接埠，預設為 3006。 |

建議將套件放在使用者可寫入的固定資料夾，避免放在 Program Files 等受保護位置。若因拒絕存取而啟動失敗，先查看 data\startup-error.log；連線設定檔的權限問題可使用「修復連線設定權限.cmd」。修復完成後，以原本的 Windows 使用者重新啟動。

開機自啟動使用 SYSTEM 執行，不需要先登入 Windows；建立／移除排程及手動停止該服務仍需管理員權限。

## 原始碼安裝與啟動

使用 Node.js 24.22.1 以上的 24 LTS（建議），或 22.23.4 以上的 22 LTS。這是 2026-10-21 官方安全更新的最低版本；`.nvmrc` 指定 24.22.1，免安裝包只接受 24.22.1 以上的 24.x 官方 x64 執行檔。在此資料夾執行：

```powershell
npm ci
Copy-Item .env.example .env
# 在 .env 填入 WebAccess 連線資料，再執行：
npm run build
npm start
```

預設連接埠是 3006，與舊版 3005 分開。請以主機實際 IP 開啟：

- 播放器：`http://主機IP:3006/display`
- 日常管理：`http://主機IP:3006/settings`，設定待機輪播與跑馬燈。
- 工程設定：`http://主機IP:3006/engineering`，建立測點、平面圖、連線及系統控制。
- 根網址會導向播放器頁。

設定頁採內網免登入；一般內容可由內網使用者修改，WebAccess 連線設定僅允許在服務主機以 localhost 操作。更改服務網址或帳號時，必須重新輸入密碼或明確清除密碼。WebAccess 帳密僅放在伺服器 `.env`，不要將 `.env` 提交或公開。

## 連線設定

| 環境變數 | 說明 |
| --- | --- |
| `HOST` | 網頁服務監聽位址，預設 `0.0.0.0` |
| `PORT` | 網頁服務連接埠，預設 `3006` |
| `WEBACCESS_API_BASE` | WebAccess JSON 服務根網址，例如 `http://SCADA主機/WaWebService/Json` |
| `WEBACCESS_PROJECT` | WebAccess 專案名稱 |
| `WEBACCESS_USERNAME` | WebAccess 使用者帳號 |
| `WEBACCESS_PASSWORD` | WebAccess 密碼，可為空字串 |
| `POLL_INTERVAL_MS` | 輪詢間隔毫秒，預設 `2000` |

未設定 WebAccess 時可先建立平面圖與測點，顯示端會標示資料連線尚未就緒。

## 操作

1. 進入工程設定頁，使用「批次上傳平面圖」一次選取所有樓層 PNG 或 JPEG，加入共用圖庫。上傳後按「儲存設定」。
2. 建立測點專屬頁面，從「共用平面圖」選用底圖，綁定一個測點 Name 並設定文字。同樓層測點可共用底圖，但使用各自的警報頁面。
3. 拖曳圖示定位，設定大小、閃爍及內建或自訂圖示。
4. 在日常管理頁批次新增 PNG、JPG、GIF、PDF 或 MP4，排序並設定圖片或 PDF 每頁的顯示秒數。單張圖片持續顯示；影片播完切換下一項，單支影片自動重播。可設定跑馬燈及聲音，再預覽並儲存。
5. 在播放器開啟顯示網址。

Name 精確匹配，出現在有效完整警報清單即觸發，消失即解除。多個測點同時觸發時顯示最新警報的獨立圖面，只顯示那一個測點的圖示與文字；解除後回到下一筆最新警報的圖面，全部解除後顯示待機畫面。取得資料失敗時保留最後畫面並標示中斷。

每頁最多一個測點，新增另一個測點請建立另一個頁面。尚未綁定 Name 的頁面不參與警報切換。先前的多測點共用頁面設定會於啟動時拆分成獨立頁面，各測點的底圖、圖示、座標及文字皆保留。

## 開發與驗證

### Node.js 安全更新

- 官方公告：https://nodejs.org/en/blog/vulnerability/october-2026-security-releases
- 更新開發主機的 Node.js 後，重新開啟終端機，以 `node --version` 確認為 24.22.1 或更新的 24.x。
- 在可連線 npm 官方站的環境執行 `npm ci`、`npm outdated` 與 `npm audit`；依漏洞修補需求更新套件及 lockfile，再執行下列測試與建置。掃描連線失敗不代表沒有漏洞。
- 重新執行 `npm run package:portable` 產生新包；更新主機上的 Node.js 不會更新舊免安裝包內的 `runtime/node.exe`。
- 案場更新前先備份並停止程式，依上方免安裝包更新方式替換 `app`、`runtime`、`tools`，保留案場資料。舊 ZIP 也仍包含舊執行環境，不應當作已修補版本部署。

```powershell
# 兩個終端機分別執行：
npm run dev:server
npm run dev

# 驗證：
npm run typecheck
npm test
npm run build
```

請備份 `data` 與 `.env`；停止程式後備份可避免與儲存操作衝突。切換正式播放器網址前，須完成 BrightSign 實機驗證。需要回復時切回舊版網址，舊版專案不會被本程式修改。

BrightSign 型號與 OS 版本尚未確認；一般瀏覽器驗證不代表播放器實機相容性。WebAccess 實際連線與主機重新開機自啟動仍須在案場確認。

## 日常待機內容

日常管理與工程設定分頁，不需登入；播放器仍沒有設定入口。原本的待機圖片會自動沿用。設定版本衝突時需重新載入，工程頁儲存不會清除待機內容。

圖片與 GIF 單檔上限 20 MB、PDF 30 MB／30 頁、MP4 100 MB。PDF 上傳時由服務主機轉成圖片，每頁最長邊 1920 像素；影片建議使用 H.264／AAC 的 MP4，實際播放能力依 BrightSign 型號及韌體而定。影片預設靜音，開啟聲音時瀏覽器可能要求互動授權。

警報出現立即停止待機影片及輪播並隱藏跑馬燈；解除後從清單第一項重新播放。影片連續 30 秒沒有播放進度時會跳過，並依媒體重試機制稍後重試。從清單移除媒體並儲存後停止播放，實體上傳檔案保留供復原。媒體暫時載入失敗時，每 30 秒允許重試；其他正常媒體會持續播放，失敗項目於後續輪播重試。

跑馬燈可選上方／下方，字體大小可輸入 12–120 像素，速度可輸入 10–500 像素／秒，數字越大越快。短公告會自動重複填滿畫面，使用等速動畫首尾銜接、無縫循環；管理頁即時預覽與待機預覽採用相同計算方式，沒有媒體時也可預覽跑馬燈。舊版 8 級速度設定仍可讀取，輸入數值後才改用像素／秒。使用「從現有媒體選取」可搜尋並重用已上傳檔案；從播放清單移除後，媒體仍留在圖庫。圖庫名稱保存於 data\media-library.json，備份 data 時會一併保留。舊檔未保存原始名稱時會顯示儲存檔名，可直接編輯播放清單中的顯示名稱，不會變更實體檔案。
